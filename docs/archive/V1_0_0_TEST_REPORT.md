## P1：按下鼠标即扣费，拖动会误解锁

- 文档 `拖动翻滚操作说明.md:97-105,267-271` 要求单击在松开时确认，拖动不会触发点击，并区分拖动阈值。
- `scripts/tech_node.gd:73-76` 仍在左键按下时直接发出 `node_clicked`；`scripts/tech_tree_manager.gd:209-217` 当场扣费，没有等待释放或确认拖动阈值。
- 实测：拥有 1000 点，在可用节点按下左键但不松开，节点立即变成已解锁，余额为 995。继续移动 100×40 像素形成拖动再松开，扣费不会撤销，解锁计数已经增加。
- 实际 OpenGL 渲染再次验证：尚未松开左键，100 点已经变成 95 点。
- 影响：尝试拖动时可能购买起点节点；界面承诺的“松开后的单击才解锁”不成立。
- 建议：以按下位置、节点身份和累计移动距离跟踪一次手势；仅在同一目标上释放、未超过拖动阈值且未取消时发出购买事件。拖动与购买需要共享手势判定，不能只改提示文字。

## P2：初始观察中心未初始化

- 文档和 `calculate_axis_center()` 指定默认纵向中心为 `(0,-30,0)`。
- `scripts/camera_controller.gd:23-28` 在 `_ready()` 中先计算相机位置，再连接信号，没有调用中心计算或当前布局初始化；`axis_center` 保持 `(0,0,0)`。
- 实测首次启动中心为零；PageDown 切换两次回到相同方向后，中心才变成 `(0,-30,0)`。角度和距离重置到同一状态，相机却移动 30 单位。
- 影响：启动视角偏向科技树顶端，与切换回同一模式后的视角不一致。
- 建议：读取实际当前方向后，先计算轴心再设置相机；初始化和重新进入同一布局使用同一条路径。

## P2：失焦后仍继续拖动

- 左键按下后 `dragging=true`；应用失焦不会清除状态。鼠标移动处理只检查 `dragging`，不检查按钮实际是否仍按住。
- 实测发送 Godot 应用失焦通知后，再发送 `button_mask=0` 的鼠标移动，视角继续旋转。Esc 也不能取消当前拖动。
- 位置：`scripts/camera_controller.gd:51-87`。
- 影响：在窗口外松开按钮或切换应用再返回，移动鼠标仍可能转动视角。
- 建议：失焦、Esc 和退出时取消手势；无左键按住的移动事件也应终止拖动。失焦测试使用 Godot 通知，没有执行操作系统级 Alt+Tab 自动化。

## P2：俯仰限制没有实现

- 文档 `拖动翻滚操作说明.md:273-277` 说明俯仰约限制在 -90° 至 +30°，不会倒转。
- `roll_depth`、`roll_vertical` 在鼠标移动时无限累加，没有夹紧；纵向倾角直接使用 `-PI/3 + roll_depth`。
- 实测在窗口内部连续三次由 `(600,600)` 拖到 `(600,100)`，倾角超过声明的上限。所有手势坐标均处于 1280×720 视口内，无需异常屏幕输入。
- 建议：限制最终有效俯仰角，避开与观察 up 向量平行的极点；横向模式也应有明确的角度限制。

## 合成滚轮松开事件的回归

`camera_controller.gd:63-70` 未过滤 `event.pressed=false`，合成松开事件会再次缩放，两个对应断言失败。普通按下事件仍可向上拉近、向下推远。本轮未确认具体鼠标硬件是否发送这类松开事件，不将其描述为所有设备都必现的问题。
