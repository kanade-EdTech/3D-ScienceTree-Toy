# 1.2.0 修复与复测报告

日期：2026-10-24。应用版本：**1.2.0**。环境：Windows、Godot 4.7.2、OpenGL Compatibility，默认视口 1280×720。

结论：六组共 **670 项检查全部通过，0 项失败**。测试与实际显卡渲染日志无脚本错误或警告。

## 本次发现与修复

- **节点单击无法解锁**：修复前通过视口真实按下/松开后，节点仍未解锁、余额不变。节点的旧按下购买逻辑已经移除，而相机改写后没有接上购买信号。恢复由相机统一记录按下目标和位置，在同一节点松开、移动不超过阈值且手势未取消时发出购买。
- **手势保护回退**：恢复 6 像素拖动阈值，拖动不购买；失焦、Esc、离开窗口、无按钮移动、缩放及切换方向会取消待购买。普通点击不改变视角，重复松开不重复扣点。
- **翻滚极点不稳定**：横向相机绕 X 轴经过正上方、正下方时，同步旋转 up 向量，避免固定全局 up 与观察方向平行。完整一周可连续通过两个极点并恢复整个变换。
- **初始视野裁切**：实际画面和测试都确认四个起始科技原先全部不在视口内。现按实际科技树范围和相机投影自动计算初始视距，在 10–70 的缩放范围内给出全景。默认视口下四个起始科技和 32 个节点中心全部可见；该设置只用于初始构图，之后仍可手动缩放和平移。
- **初始化与版本**：读取管理器实际布局，按层级和间距计算中轴；版本配置及 README 更新为 1.2.0。

保留本轮新设计：相机从上方观察；垂直左右拖动沿用本次迭代的旋转方向，灵敏度为 0.005 弧度/像素；平移速度为 0.05 单位/像素。使用统一 `get_focus_point()` 表达平移后的焦点，适配测试时不把旧字段名称或旧旋转方向当成产品缺陷。

### 交互与布局证据

- 两个方向分别通过视口鼠标按下/松开、物理射线拾取、节点信号和管理器逐步解锁全部 32 个节点；固定随机种子下总消耗均为 198 点。
- 前置不足不扣点；最后一个前置激活后继；点数差 0.1 时不能购买，恰好够用时归零；重复购买不重复扣点。
- 小幅手抖允许普通单击；拖动、Esc、失焦和切换方向取消待购买；重复释放不再次触发购买。
- 方向切换动画中和结束后，69 条连线都与节点同步；10 次快速切换后几何、材质、颜色和游戏进度保持一致。
- 平移和旋转分离，反向拖动可恢复原状态；缩放保留平移与角度。
- 横向完整旋转检查包含 0°、45°、90°、135°、180°、225°、270°、315°、360°，两个极点前后无方向跳转；垂直完整一周也保持变换一致。
- 初始可见性新增五项检查：四个起始节点逐个验证，另确认全部节点中心处于视野内。修复前五项失败，修复后全部通过。

### 实际显卡渲染

运行时读取应用版本为 1.2.0，中轴为 `(0,-30,0)`。固定测试数据下自动初始视距约为 60.38，32/32 个节点中心处于默认视口内。

上拖 100 像素使焦点上移 `(0,5,0)`；横向拖动到约 135° 的极点时，视图矩阵行列式为 1，无相机错误。鼠标松开前节点未解锁、余额 100；松开后节点解锁、余额 94，对应本次生成的 6 点成本。
