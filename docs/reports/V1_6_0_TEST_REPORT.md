## 发现与修复

### 新增体积雾与当前渲染器不兼容

修复前创建了 32 个 FogVolume，但当前工程使用 Compatibility 渲染器。实际图形运行出现：

~~~text
ERROR: shader type fog not supported in OpenGL renderer
~~~

Godot 的体积雾仅支持 Forward+；即便使用支持的渲染器，FogVolume 仍需启用环境体积雾才能显示。依据：[官方体积雾文档](https://docs.godotengine.org/en/stable/tutorials/3d/volumetric_fog.html)、[FogVolume 说明](https://docs.godotengine.org/en/stable/classes/class_fogvolume.html)。

按官方文档的 QuadMesh 替代方案，改为共享径向渐变纹理、朝向相机的加色半透明光晕。保留 OmniLight3D 的颜色、能量和范围，锁定时隐藏光晕，可用与已解锁时显示对应颜色。该效果是兼容的柔和光晕，不是真实体积散射。

纹理由 32 个节点共享，材质按节点独立；光晕不创建碰撞形状，不干扰模型拾取。最终实际 OpenGL 渲染未再出现雾着色器错误。

### 版本配置滞后

工程和数据仍标记为 1.5.0，已更新为 1.6.0，并更新 README 当前入口和版本断言。Web 包名由工程配置自动读取版本。

### 专项测试需要适配更完整的依赖关系

旧测试只覆盖前 10 个模型，并按 JSON 记录顺序购买。扩展至 26 个模型后，电磁学依赖后列出的定量化学等同层前置，直接按记录顺序会产生无效测试。

专项检查现按 JSON 依赖图排序，而不是修改正常的游戏前置条件。窗口模式还在模拟按下前同步实际鼠标位置并等待事件到达，避免物理鼠标位置与模拟事件位置不一致造成手势取消；无界面模式继续使用视口输入。游戏的失焦、鼠标离开窗口和拖动取消规则保留。

## 复测方式

README 列出全部九组命令；模型专项沿用原测试文件名 test_tier0_models.gd，当前实际覆盖 26 个模型。

~~~powershell
& "$env:LOCALAPPDATA\Programs\Godot\4.7.2\Godot_v4.7.2-stable_win64_console.exe" --headless --path . --script res://tests/test_tier0_models.gd
~~~

添加 -- --render 可执行图形检查；TECH_TREE_MODEL_TEST_OUTPUT 环境变量用于设置截图目录。测试使用 Godot 输入与物理拾取，不等同于操作系统级鼠标自动化。
