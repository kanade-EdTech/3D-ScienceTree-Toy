# 顶部四个节点模型绑定测试

日期：2026-10-25。环境：Windows、Godot 4.7.2、1280×720、OpenGL Compatibility；实际渲染设备为 NVIDIA GeForce RTX 4060 Laptop GPU。

**结论：测试未通过。** 四个模型能够加载、隐藏旧球体、跟随布局移动，解锁缩放动画也能恢复。但是存在状态更新报错、拖动误购买、模型与点击范围不一致，以及缺失模型回退不完整的问题。

本轮新增测试：[test_tier0_models.gd](../../tests/test_tier0_models.gd)。以下结果针对实际测试时的代码；scripts/tech_node.gd 的 SHA-256 为 44e0935cf7486859a7a6b657de960e93bf239ac486387cd118eb8a9845c3b79f。

## 1. 状态更新使用了不存在的 3D 属性

位置：scripts/tech_node.gd:102–106。

首次运行时，四个模型加载后进入锁定状态更新，再进入可解锁状态更新，产生 8 次相同类型的脚本错误：

~~~text
Invalid assignment of property or key 'modulate' with value of type 'Color'
on a base object of type 'Node3D'.
~~~

ModelContainer 是 Node3D，不能像 CanvasItem 一样使用 modulate。模型可用/解锁时预期的高亮没有实现。标签更新又只写在球体分支中，因此四个模型节点的可用标签没有变黄，解锁后也没有变白，仍停留在学科颜色。

建议通过模型内部 MeshInstance3D 的材质实现状态反馈，并把标签状态更新放在模型和球体共用的路径中。修改材质时应保留各模型原有配色，并避免共享材质互相影响。

启动进程的退出码为 0，但日志存在脚本错误，不能据此判定启动测试通过。

## 2. 鼠标按下即购买，拖动保护回退

位置：scripts/tech_node.gd:44、132–135。

本次绑定恢复了 Area3D.input_event 中的按下购买；相机仍保留松开购买与拖动取消逻辑，两个入口同时发出 node_clicked。该回退影响全部科技节点，而不只顶部四个。

实际视口事件复现：准备充足科技点，将鼠标移至节点，按下左键，等待两个物理帧，再拖动 80×30 像素并松开。四个节点均在按下时已解锁：

| 节点 | 按下时已解锁 | 拖动后已扣点 |
| --- | --- | ---: |
| 天文观测与航海历法 | 是 | 6 |
| 大地测量与弹道工匠术 | 是 | 5 |
| 炼金术、冶金与医药蒸馏 | 是 | 3 |
| 人体解剖与博物志 | 是 | 9 |

金额来自固定随机种子 48。由于购买已在按下发生，后续拖动、Esc、失焦均不能撤回该次购买。

普通单击还会产生按下、松开两次节点点击信号。已解锁保护阻止了重复扣款，但不能阻止提前扣款或多发信号。建议继续由相机统一处理“同一目标松开、移动未超阈值、未取消”的购买确认，Area3D 只保留悬浮事件。

## 3. 看得见的部分模型无法点击

位置：scenes/tech_node.tscn:10、29；scripts/tech_node.gd:66–90。

加载 GLB 后隐藏了旧球体，但仍使用原来半径 0.6、中心不变的球形拾取区域，没有根据模型形状、尺寸和偏移调整。

在每个模型的近景视角中，将包围矩形划为 24×24 网格。测试临时使用模型三角形的物理形状确认射线是否确实覆盖模型，再与项目原有 Area3D 拾取比较；临时形状不会接收鼠标事件，并在手势测试前移除。

| 模型 | 射线覆盖模型的采样数 | 项目拾取失败数 |
| --- | ---: | ---: |
| 罗盘 | 176 | 48 |
| 火炮 | 173 | 97 |
| 药剂瓶 | 146 | 2 |
| 骨架 | 47 | 0 |

这是所测视角的采样结果，不代表所有视角的覆盖率。火炮与罗盘的问题明显；骨架在本次视角未发现漏点。

建议根据模型包围盒设置拾取形状及中心，并为解锁脉冲留出合理余量。

## 4. 缺失模型回退球体缺少状态材质

位置：scripts/tech_node.gd:59、68–70、112–114。

测试只在临时节点实例中把 astronomy_nav 的模型路径改为不存在的路径，没有删除真实模型文件。旧球体仍然可见，但因为 tech_id 在映射表内，setup_visuals 跳过了球体材质初始化；load_model 提前返回后，后续状态更新又因材质为空而退出。

结果：回退球体没有正常的可用状态材质和黄色标签，与绑定说明承诺的回退行为不符。建议始终准备可用的球体材质，并在模型加载失败后统一刷新状态。

## 已验证正常的部分

- 四个 GLB 均加载成功，旧球体均隐藏。
- 四个模型随纵向、横向及往返布局正确移动，连接线端点保持同步。
- 模型解锁脉冲结束后 scale 恢复为 (1,1,1)。
- 两个方向都可以沿前置条件最终解锁 32/32 节点，固定种子下各消耗 198 点；但是一次鼠标单击应只产生一次信号的断言失败。
- 现有固定中轴、滚轮、拖动采样数学、点位避让相关断言未出现新的失败；这些测试运行中仍记录了上述状态更新脚本错误。
